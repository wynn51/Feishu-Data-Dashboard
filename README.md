# 电商数据链路（展示项目 · 脱敏）

本目录是「电商数据链路」项目的**脱敏展示版**：保留目录结构、Python 执行脚本与业务逻辑文档，**不含任何真实业务数据**。

项目目标：把千易 ERP、飞书人工维护表等多来源原始数据，按统一口径加工为数据中间表，最终产出**每日销售及库存跟进表**与**运营大盘数据监控表**两张结果表。

```text
源数据  ──►  数据中间表  ──►  结果表
```

核心原则：业务口径由中间表承载；最终数字必须来自 **Excel 公式计算后的缓存值**，而非 Python 重算。

## 五、脚本说明

四个脚本均为独立可执行脚本，统一用 `argparse` 接收参数，`--root` 指向项目根目录（下含 `源数据/`、`数据中间表/`、`结果表/`）。

> 代码约定：不使用类型注解、不使用 `logging`，统一用 `print()` 输出中文日志。

| 脚本 | 参数 | 输入 | 输出 |
| --- | --- | --- | --- |
| `生成每日销售及库存跟进表.py` | `--root`、`--date`（`YYYY-MM-DD`） | 商品销售统计（**D-1**）、商品销售统计_累计、库存查询（D）、入库单明细_新建/收货中（D）、入库单跟踪表（D）、映射表、@数据粒度表_每日… | `数据中间表/每日数据中间表/每日数据中间表_{D}.xlsx`；更新 `结果表/每日销售及库存跟进表.xlsx` |
| `生成月度数据中间表.py` | `--root`、`--month`（`YYYY-MM`） | 商品销售统计_{月份}、库存查询、入库单明细_收货中、映射表、@数据粒度表_运营大盘 | `数据中间表/月度数据中间表/月度数据中间表_{YYYY年MM月}.xlsx`；更新 `结果表/运营大盘数据监控表.xlsx` |
| `生成在途批次表.py` | `--root`、`--month` | 入库单明细_新建、入库单跟踪表、库存查询、A未发数据表、映射表 | `数据中间表/在途批次表/在途批次表_{YYYY年MM月}.xlsx` |
| `生成净需求计算表.py` | `--root`、`--month`、`--site`（可选，不传则生成全部站点）、`--output-dir`（可选） | 映射表、库存查询、入库单明细_收货中、中间表在途批次表 | `数据中间表/净需求计算表/净需求计算表_{站点}_{YYYY年MM月}.xlsx` |

日期规则：每日链路中**商品销售统计取 D-1**，其余源数据取 D；累计销售按 D 的日期位置取「月初至 D-1」口径。

## 六、文档与运行

| 文档 | 内容 |
| --- | --- |
| `每日销售及库存跟进表_中文逻辑脚本.md` | 每日链路完整规格：输入校验、各 Sheet 生成步骤、结果表对齐与校验、日志要求 |

**业务口径以中文逻辑脚本为准**，`AGENTS.md` 只定义执行边界。

```bash
python 代码/生成每日销售及库存跟进表.py --root "<ROOT>" --date 2026-06-30
python 代码/生成月度数据中间表.py       --root "<ROOT>" --month 2026-06
python 代码/生成在途批次表.py           --root "<ROOT>" --month 2026-06
python 代码/生成净需求计算表.py         --root "<ROOT>" --month 2026-06 --site 菲律宾
```

运行环境：Python 3.7+、`openpyxl`、Microsoft Excel（或 WPS）——中间表需由 Excel 完成公式全量计算。

## 七、脱敏与注意事项

1. 本目录不含任何真实业务数据，三个数据目录均为空。
2. 脚本中根目录的默认值统一为占位符 `<ROOT>`（如 VSCode 直接运行配置），**执行前需替换为实际路径**，或直接改用 `--root` 传入。
3. 脚本通过 `Path(__file__).resolve().parents[1]` 推导默认根目录，保持 `代码/` 位于根目录下一层即可正常工作。
4. 中间表必须经 Excel 全量计算并保存后，结果表才能读到正确的公式缓存值；不要用 Python 重算冒充 Excel 结果。
5. `源数据/` 为只读目录，脚本不应写回。
